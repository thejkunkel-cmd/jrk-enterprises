## Triangle Architecture

### White Node — Governance & Doctrine
- **Function:** Sets the rules of the room. Defines what AI can and cannot do in a given engagement.
- **Products:** Core Doctrine, Attachment Doctrine, CRC (Client Relationship Contracts), White Room Session Architecture
- **Layer Mapping:** Layer 1 (Foundation/Doctrine), Layer 2 (Governance/Compliance)
- **Deliverable Format:** Markdown documentation, signed contract addendums, onboarding SOPs

### Red Node — Action & Outreach
- **Function:** Executes. Builds pipelines, runs outreach, manages the operational cadence of client engagement.
- **Products:** Outreach Operations Tile v1.0, Stream Architecture, TESLA Protocol, Apollo.io/Zapier Integration Specs
- **Layer Mapping:** Layer 3 (Orchestration), Layer 4 (Execution/Automation)
- **Deliverable Format:** Campaign specs, decision tree docs, pipeline architecture maps

### Blue Node — Custody & Memory
- **Function:** Holds. Manages session memory, asset containment, resonance logs, and model handoffs.
- **Products:** App Stack v1.0, Integrated Consoles, VELA Protocol, Resonance Logs, Room Handoff Architecture
- **Layer Mapping:** Layer 5 (Memory/Storage), Layer 6 (Custody/Attribution), Layer 7 (Resonance Tracking)
- **Deliverable Format:** Session logs, provenance records, model interaction archives

## Security & IP Doctrine

- All client engagements operate under the **Attachment Doctrine**: AI is a channel, not a party. The human remains the named author and decision-maker.
- All session outputs are logged under the **Unnamed Credit System**: attribution is tracked even when not surfaced publicly.
- **Cross-contamination rule:** External commercial projects are ring-fenced. Internal system architecture is never exposed in client deliverables.
