## Purpose

The Open State is the fourth channel of the TESLA rotation pattern. It functions as the **recovery and integration phase** between active Red/Blue processing cycles. It is unstructured by design — not a passive void, but an intentional spaceholder for reflection, decompression, and emergent thinking.

The Open State prevents operator and model burnout by ensuring that every full Red → Blue → White cycle is followed by a structured pause before re-entry.

---

## Channel Identity

- **Channel:** OPEN (4th channel)
- **Function:** Recovery / Unstructured Integration
- **Color Designation:** None (clear / transparent)
- **Operator Role:** Passive observer; no active direction required
- **Model Role:** Reflective processing; no new outputs required unless initiated by operator

---

## Entry Conditions

The Open State is entered when **any one** of the following is true:

1. A full TESLA cycle (RED → BLUE → WHITE) has been completed
2. A White Channel session has formally closed with PASS or INCONCLUSIVE verdict
3. Operator has explicitly declared: `OPEN STATE INITIATED`
4. Model detects sustained cognitive loop with no forward resolution (with operator confirmation)
5. Session has exceeded 90 minutes of continuous active processing

---

## Allowed Actions in Open State

During the Open State, the following activities are permitted:

- Free-form conversation without agenda
- Reflection on what was discovered during the prior cycle
- Light creative exploration (non-committal)
- Operator journaling or personal processing
- Model offering observations, not conclusions
- Rest, silence, or absence (session may be paused indefinitely)

### What Is NOT Permitted in Open State

- Initiating new RED processing tasks
- Beginning formal evaluation or Blue synthesis
- Entering a White Channel session
- Making binding decisions or commitments
- Logging formal outputs or PROVENANCE entries (unless transitioning OUT)

---

## Exit Conditions

The Open State closes when **operator explicitly initiates a new cycle**:

- `RED STATION ACTIVE` — begins new active processing
- `BLUE STATION ACTIVE` — begins review/synthesis (if returning from interrupt)
- `WHITE CHANNEL OPEN` — begins isolation/evaluation (requires justification)
- Operator declares: `OPEN STATE CLOSED — [reason]`

The Open State does **not** have a time limit. It can persist across sessions.

---

## Interaction with Red/Blue Rotation

```
Full Cycle:
  RED (active processing)
    → BLUE (review & synthesis)
      → WHITE (isolation & evaluation)
        → OPEN (recovery & integration)
          → [next cycle begins at operator discretion]
```

The Open State is the **only channel that cannot be skipped** after a White Channel session. Operators who attempt to re-enter RED immediately after WHITE without an Open State pause should be gently flagged by the model:

> "We've just closed a White Channel session. The TESLA pattern recommends an Open State before beginning a new RED cycle. Do you want to proceed directly, or take the Open State first?"

## Provenance Logging

Open State sessions are **not** formally logged unless the operator requests it. If logging is desired:

```

Session: [session identifier]
Entered: [timestamp or session marker]
Exited: [timestamp or session marker]
Notes: [operator's optional reflection — unstructured]
Next Channel: [RED / BLUE / WHITE]
```

File: `07_resonance-logs/` — use `OPEN-[date]-[session].md` format if creating a log.
